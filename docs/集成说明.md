## 规则要点（对齐 A）

- 37 点、76 边，9 行 × 5 列；`1` 虎（王）、`2` 羊（大臣）、`0` 空。
- 开局 2 虎在 (2,2)、(6,2)，8 羊在场 + 16 只手牌 = 24。
- 虎先手；吃满 10 羊虎胜；300 步和棋；当前方无合法走法则对方胜。
- 跳吃必须是「虎—羊—空」三点共线且相邻格距 1；`("eat", frm, over, to)` 显式带被吃点，
  不像旧原型那样靠遍历邻居猜。
- phase 1 = 羊添子，phase 2 = 双方走子；`inHand` 与 phase 必须一致，后端会校验。

## D 的算法（mod1/）

算法按版本目录组织，第一版在 `mod1/`，对外统一暴露 `NAME`、`choose_move(game)`、`evaluate(game)`：

- `mod1/generate_moves.py`：走法**生成 + 启发式排序**。生成直接调 `Game.legal_moves()`——规则只有 A 一份，
  不写第三套；排序按行棋方的口味打分（吃子 10000 > 走子 100 + 中心差 > 添子：抱团加分、贴虎扣 3 倍），
  好步先搜，剪枝更狠。另有 `game_from_state(board, phase, player, remaining_sheep)` 把旧四参数还原成 `Game`。
- `mod1/rule_based.py`：Alpha-Beta + 迭代加深（`TIGER_DEPTH`，默认 4）+ 软限时（`TIGER_TIME_LIMIT`，默认 1.0s），
  超时抛内部 `_Timeout`，保留上一层结果；每一层用 `generate_moves(game)` 拿排好序的走法。
- `mod1/evaluate.py`：E 的评估（权重 120/40/12/18/6），非终局直接用；终局 `WIN_SCORE - game.moves`（越快赢分越高），羊方取相反数。
- `mod1/minimax.py`：旧四参数签名 `get_best_move(...)` 的兼容层。
- 搜索全程 `Game.copy()`，不修改调用方棋局（有测试守着）。
- **加新算法**：建 `mod2/`（例如 MCTS），同样暴露 `NAME` / `choose_move` / `evaluate`，再在 `engines/` 下建一行转发壳
  （如 `engines/mcts.py`：`from mod2.rule_based import choose_move, evaluate`），`$env:TIGER_ENGINE='mcts'` 即可切换。
  C 的 `engines/adapter.py` 是原样保留的：它按 `engines.<TIGER_ENGINE>` 动态导入并返回 `(走法, 引擎名)`，默认名 `rule_based`，
  所以 `engines/rule_based.py` 这个转发壳必须留着，删了默认引擎就 `ModuleNotFoundError`。
- 前端"自选模式"目前**没接线**：`templates/index.html` 只有 ai/human 两个下拉，`app.py` 的 `compute(g)` 也只调 `choose(g)`。
  要做需要 B 加下拉、C 把请求里的引擎名传下去，D 这边不用再动。

## 旧代码怎么处理

- `legacy/` 里是旧 9 点原型的存档，只做参考，不参与运行。
- 根目录的旧 `mini_graph.py`、`evaluate.py`、`generate_moves.py`、`minimax.py` 已不存在；评估与生成层现在在 `mod1/` 里。
- 旧 `generate_moves.py` 的 eat 走法漏了 `over` 字段、`make_move` 靠邻居猜被吃子，这两处 bug 在新 `core/rules.py` 里已经不存在，不要再用旧逻辑。

## 环境与踩坑

- 本机 `.venv` 为 Python 3.12.10 + Flask 3.1.3；系统 `python` 没装 Flask，务必用 `.venv\Scripts\python`。
- 端口固定 5000，`GET /api/state` 返回的是**新局初始状态**，不是服务器保存的当前局：状态由浏览器持有，这样才支持悔棋、重开、双人模式。
- `/api/ai` 是异步任务：POST 拿 `taskId`，再轮询 `/api/tasks/<id>`；前端 `api.js` 最多等 60s。
- `static/js/board_data.js` 由 `scripts/export_board.py` 从 `core/board.py` 生成，改棋盘拓扑后必须重跑，否则前端坐标系和后端规则会错位。
- 本次合并的两个沙箱限制（不是代码问题）：
  1. 会话内对 `.git/` 的写操作被拒（`index.lock` 权限拒绝），所以合并没有做成 commit；
  2. 会话开始前就存在的文件不能删除/重命名，所以根目录那 4 个旧 `.py` 用「覆盖成桩」而不是删除，`.gitignore` 也未能复制进来。
  清理这 4 个桩文件、补 `.gitignore`、提交，需要你在本机自己执行。
